# Етап 1. Discovery Phase

## Міні-пітч

**Проблема.** Студент чи інді-розробник написав десктопну програму на Qt і хоче продавати її. Без захисту один куплений exe копіюють на десятки ПК. Готові сервіси ліцензування платні, працюють лише через інтернет, а дані покупців лежать на чужому сервері.

**Рішення.** «Сервер ліцензій» — локальний сервер з панеллю адміністратора і клієнтський модуль з двох файлів. Розробник видає ключ у вікні, покупець вписує його в `license.json`, програма при старті питає сервер і прив'язується до одного ПК. Блокування, скидання прив'язки, пошук — у кілька кліків.

**Для кого.** Розробники невеликих Qt-програм (студенти, фрилансери, мала студія), яким треба просте ліцензування без підписок і без власного бекенду.

## Аналіз аналогів

| Критерій | Keygen.sh | Cryptolens | LicenseSpring | **Наш сервер** |
|---|---|---|---|---|
| Тип | Веб-SaaS + REST API | Веб-SaaS + SDK | Веб-SaaS + SDK | Десктоп (Qt) + модуль |
| Ціна | Безкоштовно до ліміту, далі від $49/міс | Від ~$30/міс | Від ~$90/міс | Безкоштовно |
| Робота в локальній мережі без інтернету | Тільки self-hosted (Docker, PostgreSQL, Redis) | Ні | Ні | **Так** |
| Прив'язка до ПК | Так (machines) | Так | Так | Так (HWID = SHA-256 від id системи) |
| Захист від підробки відповіді | Підпис Ed25519 | Підпис RSA | Підпис | HMAC-SHA256 + nonce |
| Інтеграція в Qt | Самому писати HTTP-код | C++ SDK (не Qt) | C++ SDK | **Один виклик `requireLicense()`** |
| Де зберігаються дані покупців | У постачальника | У постачальника | У постачальника | У себе, `licenses.json` |

**Висновки.** Аналоги потужніші (тріали, підписки, аналітика), але для маленької програми вони надлишкові, платні й залежать від інтернету. Ніша нашого MVP — «поставив і працює» в локальній мережі чи на домашньому сервері.

## Чому зручно і що закладено в архітектуру

- **Мінімум кроків для розробника**: скопіювати 2 файли, додати 1 рядок у `main()`.
- **Мінімум кроків для адміна**: одна сторінка — статистика, пошук, фільтри, деталі, дії.
- **ООП-переваги**:
  - доменне ядро (`License`, `LicenseStore`, `LicenseServer`) зібране в окрему бібліотеку `licensecore` без залежності від Qt Widgets, тому інтерфейс можна замінити (наприклад, на веб чи консоль), не чіпаючи логіку;
  - кожен клас має одну відповідальність (модель / сховище / мережевий протокол / вікно);
  - GUI дізнається про зміни через сигнал `changed()` (Observer), а не опитує сервер;
  - сховище передається в сервер і вікно ззовні (впровадження залежності), тому в тестах той самий сервер працює з тимчасовим файлом.
