# Етап 5. Data Layer

Обрано два варіанти із завдання:

1. **Серіалізація в JSON** (`QJsonDocument`) — сервер зберігає ліцензії в `licenses.json`, клієнт читає `license.json`.
2. **Мережева інтеграція** — клієнт шле запит через `QNetworkAccessManager`, сервер приймає його на `QTcpServer`.

## Схема `licenses.json` (сервер, лежить біля exe)

Корінь — об'єкт, де ключ — ліцензійний ключ, значення — дані ліцензії. Так пошук за ключем має ту саму форму, що й `QMap` у пам'яті.

```json
{
  "LIS-3F2A-91C0-7B1D": {
    "owner": "Іван Петренко",
    "note": "Повна версія, оплата 12.11",
    "blocked": false,
    "hardware_id": "a91c3e0f5b7d24e6c8a1f09b3d5e7c21",
    "created_at": "2026-11-12T10:15:00",
    "activated_at": "2026-11-12T10:40:00",
    "last_seen": "2026-11-22T09:05:00"
  }
}
```

| Поле | Тип | Опис |
|---|---|---|
| *(ключ об'єкта)* | string | `LIS-XXXX-XXXX-XXXX`, XXXX — 4 hex-цифри, унікальний |
| `owner` | string | Власник, обов'язковий |
| `note` | string | Примітка, може бути порожньою |
| `blocked` | bool | Ліцензію заблоковано |
| `hardware_id` | string | HWID ПК; порожній — ще не активована |
| `created_at` | ISO 8601 | Дата видачі |
| `activated_at` | ISO 8601 / `""` | Дата прив'язки до ПК |
| `last_seen` | ISO 8601 / `""` | Остання успішна перевірка |

Відповідник у пам'яті: `QMap<QString, License>` у `LicenseStore`; перетворення — `License::toJson()` / `License::fromJson()`.

**Цілісність даних.** Файл перезаписується після кожної зміни. Якщо при запуску JSON пошкоджений, `load()` повертає `false`, і програма закривається з повідомленням, *не* перезаписуючи файл порожнім — дані можна виправити вручну.

## Схема `license.json` (клієнт, біля захищеної програми)

```json
{
  "key": "LIS-3F2A-91C0-7B1D",
  "server": "http://127.0.0.1:8099"
}
```

## Протокол `POST /api/verify`

Запит:

```json
{ "license_key": "LIS-3F2A-91C0-7B1D", "hardware_id": "a91c3e0f…", "nonce": "6f1c…-uuid" }
```

Відповідь (ключі в алфавітному порядку — так їх серіалізує `QJsonObject`, тому підпис однаковий в обох сторін):

```json
{ "hwid": "a91c3e0f…", "message": "OK", "nonce": "6f1c…-uuid", "status": "valid", "sig": "<HMAC-SHA256 hex>" }
```

| `status` | Коли |
|---|---|
| `valid` | Ключ дійсний і прив'язаний до цього ПК (або щойно прив'язався) |
| `invalid` | Ключа немає в реєстрі |
| `blocked` | Ліцензію заблоковано |
| `hwid_mismatch` | Ключ уже прив'язаний до іншого ПК |
| `error` | Порожній ключ або HWID |

`sig` = HMAC-SHA256(компактний JSON відповіді без `sig`, спільний секрет). Клієнт довіряє лише відповіді з правильним підписом і своїм `nonce` — підроблений сервер чи повтор старої відповіді не пройдуть (це перевіряє тест `tests/tests.cpp`).
